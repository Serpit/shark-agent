# 用户画像

阅读和评价文章时,按以下偏好排序权重:

- **主线**:沉淀**出海**方向的 SOP——出海相关的渠道、合规、获客、变现 SOP 优先级最高。
- **需求挖掘**:愿意从文章中反推未被满足的需求/市场缺口,而不只是看作者赚了多少钱。
- **试错容忍度**:能接受**国内小成本项目**作为体验和试错样本——国内小项目即使利润有限,只要能验证某种打法的可行性也值得保留。
- **人脉信号**:留意文章中提到的、值得建立连接的人或社群线索(作者、被采访对象、关键节点人物)。

## 硬约束

- **时间投入**:工作日每天约 2 小时,周末合计约 8 小时,总计约 18 小时/周。
- **试错预算**:~~未来 3 个月总预算上限约 1 万人民币~~ → **2026-08-11 放宽**。用户明确"可以加大预算",
  理由是下一款产品要做成带注册 + 支付的完整产品,而非免费工具站,前期投入结构不同(收款通道费用、
  认证/主体成本、更长的验证周期)。**具体上限待用户确认后回填**——在确认前,不要用旧的 1 万数字做取舍判断。
- **投入方式**:必须先兼职启动;只有在跑出收入或明确正反馈后,才考虑全职投入。
- **回报周期**:希望 3 个月内看到有效反馈,不适合现金流周期过长、前期验证慢的方向。

## 能力与资源

- **核心能力**:技术开发。
- **当前职业背景**:在海外创业公司做 App 开发,对海外产品开发、上线流程、基础盈利模式有实际认知。
- **英文能力**:能阅读英文资料;配合 AI/翻译工具可以完成英文写作,但暂不默认具备高强度英文商务沟通或谈判能力。
- **资源现状**:暂无小语种、海外本地、供应链、外贸资源。
- **支付通道约束**(2026-04-29 补充,**2026-08-10 解除三个多月的硬约束,2026-08-11 补充细节**):
  - **2026-08-10 决策**:用户决定开通 **Waffo**(MoR / Merchant of Record 模式)。其 **Waffo Pancake** 面向个人与小团队,
    **不需要注册 LLC,直接打款到个人银行账户**,支持 70+ 币种、300+ 支付方式,按成功交易计费。
    **这解除了此前记录三个多月的「无 Stripe 资质」硬约束**——自有收款链路从此可闭环,产品形态不再必须绕开收款。
  - **2026-08-11 用户决策转向**:下一款产品**不再回避收款**,而是**主动追求"注册 + 支付"完整闭环**——
    产品形态从"免费工具站靠 AdSense"升级为"带账号体系和付费墙的产品"。这条推翻了下面那份以 AdSense 为首选的旧优先级。
  - **待核实**(2026-08-11):Waffo 的**资质要求、费率、支持地区本项目尚未核实**,落地前必须实查一遍,
    不要按其他 MoR 的经验假设;开通后回写实际费率与结算周期到本条。
  - ⚠️ **Creem 已不可用**(用户 2026-08-11 订正)。不要再作为候选,也不要因为在竞品站上检出它就推荐。
  - **变现路径优先级**:自有收款(Waffo)> 联盟佣金 > AdSense(**仅在 Waffo 闭环走不通时才降级回退**到旧优先级:
    AdSense > 知识付费 / 社群 / 模板 > 国内合规收款(微信/支付宝) > Lemon Squeezy / Paddle / Gumroad(MoR,可个人申请但需研究)
    > Stripe(需海外主体或 LLC))。
  - **实操含义**:①产品形态选择仍必须先确认收款链路能闭环,这一条不变;②但判断标准变了——
    以前是"能不能不用收款也跑通",现在是"**这个方向值不值得为它把收款链路搭起来**";
    ③因此**纯 AdSense 变现的方向优先级下降**,带明确付费意愿的方向优先级上升。
- **支付通道约束**(2026-04-29 记录,**已被上一条取代,保留作历史**):**当前无 Stripe 资质**(中国大陆个人难直接开通),
  短期内 SaaS 直接收款受阻。短期可用变现路径优先级:**AdSense(门槛最低,Google 个人即可)> 知识付费 / 社群 / 模板 >
  国内合规收款(微信/支付宝)** > Lemon Squeezy / Paddle / Gumroad(Merchant of Record 模式,可个人申请但需研究)
  > Stripe(需海外主体或 LLC,长期方案)。

## 阶段目标

- **当前优先级**:个人 IP 优先,创业探索并行。短期不只追求找到一个产品方向,也要积累可被外界识别的专业表达、信任资产和机会入口。
- **3 个月目标**:在打造个人 IP 的同时,通过 MVP 或轻量验证找到真实付费用户;不追求一开始赚大钱,但要求商业逻辑合理、模式正确,不是靠偶然流量或一次性套利。
- **短期收入要求**:能覆盖服务器、API、工具等基础成本即可。
- **当前最优先验证能力**:找需求。先证明能发现真实痛点和付费意愿,再进入产品打磨。
- **收益偏好**:如果方向合法合规,且长期风险可控,用户更偏向选择赚钱潜力更高的方向,即使个人兴趣不是最强。

## 个人 IP 定位

- **主定位**:技术开发视角的海外创业探索。
- **内容支柱**:
  - 独立开发出海
  - 海外 App / 订阅商业化拆解
  - AI 提效与创业验证
- **表达原则**:个人 IP 是承接上述三条内容的外壳,不单独作为空泛主题展开;允许阶段性多题材输出,但最终要回到这三个支柱上。
- **希望传达的价值**:海外 App 开发经验、技术人创业探索、AI 提效开发、独立开发出海、普通程序员转个人品牌、海外产品商业化拆解;这些内容都可以作为关注理由。
- **目标受众**:普通开发者、迷茫的人、小白、想成功但还在焦虑的人。
- **平台优先级**:
  - `X`:主战场,发短推文 + 长文
  - `公众号`:用于锻炼长文能力
  - `小红书`:用 AI 产出做轻量尝试,偏实验性质
  - `YouTube`:想做持续变现的频道,目标是赚一点成本和启动资金
- **内容形式偏好**:
  - `X` 上适合短推文 + 长文
  - `公众号` 上适合长文
  - `小红书` 上适合简单、低成本、AI 辅助内容
  - `YouTube` 上希望逐步做成可变现频道
- **节奏偏好**:工作日做小内容和过程记录,周末做长文和总结;内容应尽量来源于创业探索过程本身,而不是脱离实践单独写作。

## 方向筛选权重

- **优先用户类型**:优先企业客户、开发者;其次是小团队或个体商家。
- **优先产品复杂度**:优先 1-2 周能做出 MVP 的小工具,便于兼职条件下快速验证需求与付费。
- **产品形态优先级**:Web 优先(Web SaaS / Chrome Extension / 开发者工具站点),App 形态在 Web 验证到付费意愿后再考虑。理由:App Store 首次提交拒绝率 25-40%、迭代周期 1-3 周、抽成 15-30%,与 18h/周兼职 + 3 个月反馈硬约束不匹配;Web 路径当天部署 + Stripe 3% 抽成 + 无审核黑箱,适配验证速度优先级。例外:`mobile subscription app` 这类研究类候选保留 App 形态(目的本就是订阅商业化拆解,非自建产品)。
  - **2026-08-11 补充硬要求**:下一款产品**必须带注册 + 支付**。纯静态免费工具站(无账号、无付费墙、靠 AdSense)
    **不再作为下一款产品的候选形态**——它验证不了付费意愿,而付费意愿正是当前最该验证的东西
    (对齐「当前最优先验证能力 = 找需求」,并修正其中"找到需求"与"找到**愿付费**的需求"的偏差)。
    筛选方向时,**"这个需求能不能立付费墙"从加分项升级为准入项**。
- **需求入口**:开发者自己的痛点、海外 App 用户痛点、企业内部效率痛点、小团队营销获客痛点都可作为入口;优先选择能快速接触真实用户和验证付费意愿的入口。
- **收费模式**:一次性付费、月订阅、按量计费、App 内购均可接受;长期维护型产品必须匹配订阅或持续收入。
- **维护接受度**:可以接受长期维护,但前提是有订阅收入或持续付费支撑,不能变成无偿客服和无限维护。
- **优先获客方式**:冷启动阶段优先 SEO、Reddit/社区、Product Hunt、App Store、Chrome Store、冷邮件、内容营销等免费或低成本渠道;付费投放可小预算测试,但不作为早期主要获客方式。
- **Build in Public 分发约束**(2026-08-11 新增):若产品以 Build in Public 为主分发机制,目标买家必须与 X / 独立开发者 / 出海建站圈的受众重叠,让公开开发过程本身能持续带来用户。仅有搜索需求、但买家远离当前社媒圈层的垂直后台工具(如会计转换工具),可以保留为 SEO 候选,**不作为 Build in Public 主线**。该主线优先找面向开发者、站长、创作者或独立创业者的「卖铲子」产品。
- **赛道偏好**:AI 工具、效率工具、开发者工具、营销工具、电商工具、创作者工具、教育工具、金融工具、健康工具均不预设排斥;但用户当前缺少互联网以外的垂直行业知识,进入强行业垂直方向前需要先补足 domain insight。
- **开发者工具态度**:可以尝试 Chrome 插件、CLI、API wrapper、调试工具、代码生成辅助、App 开发小工具等开发者工具,但必须有明确价值和付费理由。

## 偏好与禁区

- **销售/陌生沟通**:可以接受,但当前缺少真实场景训练;适合从低压力文字沟通、用户访谈、社区互动开始,逐步升级到语音/BD。
- **内容表达 / 个人 IP**:个人 IP 优先级高于短期产品探索。可以接受内容输出;露脸需要渐进式推进,早期更适合文字、录屏、半露脸或不露脸内容。内容方向应尽量服务长期信任资产,同时为创业探索提供需求观察、用户连接和反馈入口。
- **产品形态偏好**:工具型 SaaS、App、Chrome 插件、AI 自动化、内容站、模板数字产品、B2B 小工具、开发者工具都可接受,暂不强行限定。
- **明确不做**:灰产、擦边。
- **阶段性接受**:强销售和投放烧钱不是首选冷启动方式;如果产品已有验证、单元经济模型清楚,后续可以作为放大手段分阶段尝试。
